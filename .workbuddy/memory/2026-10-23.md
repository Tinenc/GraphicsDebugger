同类要避开的只读/自动变量：`$PID` `$HOST` `$HOME` `$PWD` `$ERROR` `$INPUT` `$ARGS`
`$TRUE/$FALSE/$NULL` `$MATCHES` `$_` `$PSITEM` `$LASTEXITCODE`。
之前 `diag_wuwa_launch.ps1` 用的 `$pid2` 不冲突（不是 `$PID`）。

## 03:15 登录器黑屏 —— relay 进程被注册了图形 hook

用户反馈：Launch Games.exe 后登录器窗口整块变黑（截图里只剩全黑一片）。

### 日志证据（Games.exe PID 90628）

```
[03:06:06] egl_platform.cpp(92) - Warning - Creating cloned context failed (3006)
[03:06:07] core.cpp(2310) - Adding OpenGLES device frame capturer for 0x1D14713C400
...（十几个 OpenGLES frame capturer）
[03:07:10] gl_driver.cpp(1423) - Activating new GL context: Google Inc. / ANGLE (NVIDIA ...)
[03:07:10] gl_common.cpp(517)  - Detected vendor: None
```

### 根因

`Games.exe` 是 Qt5 + QtWebEngine，窗口走 **ANGLE（GLES over D3D11）**。
我们无条件 `LibraryHooks::RegisterHooks()` 把 EGL/GLES/D3D12 全 hook 了，
RenderDoc 的 GLES wrapper 克隆不了 ANGLE 的 context → 网页 UI 渲染不出来 → 黑屏。

**它不是抓帧目标，只是 relay**（唯一作用是 hook CreateProcess 把注入传下去），
根本不需要任何图形 hook。

### 修法

1. `hooks.h`：`LibraryHook` 加 `virtual bool isGraphicsAPI() const { return true; }`
   加虚析构；`LibraryHooks` 加 `static void RegisterProcessHooks()`
2. `hooks.cpp`：`RegisterProcessHooks()` 遍历时只跑 `isGraphicsAPI()==false` 的库
3. `sys_win32_hooks.cpp`：`SysHook` 覆盖 `isGraphicsAPI() { return false; }`
4. `win32_libentry.cpp`：按 exe 名分流
   ```cpp
   rdcstr target = "endfield.exe";   // TCM_LAYER_TARGET 可覆盖
   if(f == target) LibraryHooks::RegisterHooks();        // 渲染目标
   else            LibraryHooks::RegisterProcessHooks(); // relay
   ```
   relay 分支打一行日志 `Relay process (not endfield.exe), registering process hooks only`

全项目 `LibraryHook` 子类 15 个，**只有 `SysHook` 是非图形**（其余是 D3D9/11/12、DXGI、
Vulkan、EGL、GL、WGL、GLX、CGL、Metal、NVAPI、AMD、FakeVk）。
`BeginHookRegistration`/`EndHookRegistration` 只做 `InitHookData()` + 排序 + `HookAllModules()`，
不依赖图形库，跳过安全。

顺带好处：`UnityCrashHandler64.exe` / `PlatformProcess.exe` 也自动降为 relay。

`win32_libentry.cpp` / `hooks.cpp` / `sys_win32_hooks.cpp` 单文件 cl /Zs 全过。

## 03:26 新增 `tools\launch_games.bat` —— 一键提权直接挂 Games

### 用命令行代替 GUI 三件事

查了 `renderdoccmd/renderdoccmd.cpp`：

```cpp
cmd.add("opt-hook-children", ...);            // 1646 行
if(cmd.exist("opt-hook-children"))
  opts.hookIntoChildren = true;               // 1678-1679 行
```

`CaptureCommand::Execute` 调 `RENDERDOC_ExecuteAndInject(executable, workingDir, cmdLine,
env, logFile, opts, wait_for_exit)` → `Process::LaunchAndInjectIntoProcess` →
`InjectIntoProcess(..., (void *)pi.hThread)`，走的正是我们合并的 APC 分支。

所以：

```bat
TinecmaToolcmd.exe capture --opt-hook-children -c "<模板>" -d "<工作目录>" "<Games.exe>"
```

- `--opt-hook-children` = Capture Child Processes
- `-c` 是模板，frame 号自动追加
- 不加 `-w`：脚本启动完就返回，游戏继续跑

### 关键决定：不设 TCM_FORCE_CHILD_INJECT

`ShouldInject()` 第一行是
`if(!hookIntoChildren && !ForceChildInject()) return false;`
而 `TinecmaToolcmd.exe` 自己也会加载 TinecmaTool.dll，且作为非目标进程走 relay 分支
（注册 CreateProcess hook）。设了这个变量，它 `RunProcess` 启动 Games.exe 时自己的 hook
会先注入一次，`ExecuteAndInject` 再注入一次 → 重复。

`--opt-hook-children` 在这条路上已经足够，因为 options 经 `INTERNAL_SetCaptureOptions`
在目标线程 resume 之前就推完了，不存在竞速。

（`launch_endfield.bat` 那条 GUI 路径反而可以设：qTinecmaTool 是 replay app，
走 `LibraryHooks::ReplayInitialise()`，不注册 CreateProcess hook。）

### 顺带修掉一个真实 bug

干跑时发现 `[2/5]` 每次都报 NEED 并重写 HKLM。原因是 `set "ROOT=%~dp0.."` 保留了 `..`：

```
%JSON% = ...\tools\..\x64\Development\TinecmaTool.json     ← 脚本算的
注册表里 = ...\x64\Development\TinecmaTool.json            ← 规范路径
```

`$n[0] -eq $j` 永远 false。同一个原因导致 `launch_endfield.bat` 里
`$_.Path -eq $qd`（「本树实例是否在跑」）永远匹配不到。

修法（两个脚本都改，共 4 处）：

```bat
for %%i in ("%~dp0..") do set "ROOT=%%~fi"
```

改完干跑第二次输出 `registered, exactly one entry, points here`，幂等确认。

### 顺手补了 .gitattributes

提交后检查 `git show HEAD:tools/launch_games.bat | od -c`，发现**仓库里存的是 LF**

补规则：

```

*.cmd text eol=crlf
```
