### 校验判据分析

### 两个技术事实（决定方案）
1. **进程 ancestry 子进程改不了**：父 PID/父镜像名是内核建进程时写死的，hook 无法在 Child 里伪造"我是 launcher 启动的"。RenderDoc Launch 链根上是 qTinecmaTool，爬不到真 launcher → assert
2. **命令行 token / 环境变量可以改**：若判据是后者，hook 壳的 `CreateProcessW`，在拉 Client-Win64 前把 launcher 的 token 塞进 `lpCommandLine` / 环境块即可 —— 即用户要的"在传导到下一个之前伪装"

## 19:45 推翻 10-20 的「父进程链」结论：报错真因是缺 -krqlv 参数

用户贴了一份「改名绕过鸣潮检测」的文章，说文章方法能成、他不行。核对后确认：

- `kuro: Use launcher to start game!` 不是 ancestry / 反作弊检测，而是 3.7 起资源分档（HD/SD/UHD）后必须带 `-krqlv=<hd|sd|uhd>` 启动参数
  - 上游 CLI 管理器 FAQ 原文逐字一致：`Fatal error: [File:Unknown] [Line: 54] kuro: Use launcher to start game!`，缺参数即崩在 pak 挂载之后
  - 本机 `Client/Content/` 只有 `HD/`（无 SD/UHD）→ 档位必须是 `-krqlv=hd`
  - 与 crash context 的 SecondsSinceStart=0 / CommandLine 空完全吻合；10-20 记的「爬父链找 launcher 镜像名」是误判
- 文章作者的差别不在改名清单，而在启动对象 + 启动参数：直接 Launch 壳 `Wuthering Waves.exe` 时壳不补这个参数 → Client 断言；且壳会拉起 `ACE-Setup64.exe`，开 Capture Child Processes 就把它也注了 → ACE 重装驱动杀游戏
